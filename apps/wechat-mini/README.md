# 智为康乐微信小程序

底部五个入口是设备、训练、课程、商城和我的。联网或离线打开小程序时，Tab 图标均从本地包加载。连接 BS-BT91 并完成中心校准后，可进入「四方挥腕挑战」「8字轨迹跟随」「森林溪谷漂流」或「欢乐卡丁车」，完成后在本机查看详细结果和回放。课程支持图文跟练、本地打卡和进度汇总，商城展示现有商品和演示价格。

## 本地命令

使用 Node.js 22 或更新版本及 npm。在仓库根目录打开终端，执行以下命令。

```powershell
cd apps/wechat-mini
npm ci
npm run typecheck
npm run lint
npm run build
npm run verify:build
```

日常开发可运行 `npm run dev`，保存源文件后会更新 `dist/` 中的微信工程产物。

## 导入微信开发者工具

1. 先运行 `npm run build`，或启动 `npm run dev` 并等待首次编译完成。
2. 在微信开发者工具选择 **导入项目**，目录选择 `apps/wechat-mini`。工具会按 `project.config.json` 的 `miniprogramRoot` 从 `dist/` 加载编译产物。
3. `touristappid` 是开发占位值。如果开发者工具无法使用占位值导入，可在本机设置 `TARO_APP_ID` 为有开发权限的 AppID，再执行构建并导入生成的 `dist/`。该变量只进入本地构建产物。
4. 点击 **编译** 后依次切换五个 Tab，确认设备状态、训练入口、课程、商品和本地历史页面可以打开。

构建扫码预览包时，在小程序目录中设置自己的预览 AppID。构建结果和开发者工具的本地私有设置由 Git 忽略。

```powershell
$env:TARO_APP_ID = '<有预览权限的 AppID>'
npm run build
npm run verify:build
```

[Taro 微信小程序开发说明](https://docs.taro.zone/docs/GETTING-STARTED) · [微信项目配置说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)

## 与原 APP 的关系

小程序使用自己的 `package-lock.json`、入口和构建配置，跨页设备与前后台状态由 Pinia 管理。`@/shared/core` 指向仓库的公共入口 `src/core/shared.ts`。仓库根目录的 `npm run typecheck:shared` 会独立检查 Core 和四款游戏共享控制器的类型与依赖。APP 使用 Pixi 渲染，小程序使用原生 Canvas 2D。原 APP 仍从仓库根目录执行 `npm run build` 和 `npm test`。

## 版本更新与全局设备状态栏

「我的 → 关于与更新」显示当前版本及微信原生检查、下载和更新状态。正式环境优先使用微信返回的版本号。开发版和体验版显示构建号及环境标识。微信重新打开小程序时自动检查并下载可用版本。

收到更新后，仅在五个主 Tab 或已保存的结果页可见、且训练、个人活动范围、蓝牙、数据写入及切页操作均结束时提醒。点「稍后更新」后，本次前台停留期间可在「关于与更新」手动确认。确认更新会先清理蓝牙及屏幕常亮，再由微信重新打开小程序。已保存的训练记录和个人活动范围继续从本机读取。

五个 Tab 的渐变页头固定在正文上方，设备菜单可直接在当前 Tab 扫描、更换设备或前往设备管理。电量显示来自设备读数，未知时显示 `--%`，20% 及以下提示低电量。横屏训练只显示紧凑状态，掉线后须恢复原设备、重新校准中心，再手动继续。

首次使用需手动选择设备。已有绑定可按本机设备 ID 自动恢复。主动断开会保留绑定并在重新打开小程序后继续暂停自动重连，手动连接成功后恢复。微信或手机明确拒绝蓝牙权限、蓝牙关闭时，由用户到设备页处理。旧基础库无法查询权限时，有效绑定可进行一次受控恢复，授权提示取决于系统。

### 修改小程序发布版本

## BS-BT91 真机验收

在 Android 和 iOS 微信分别记录系统与微信版本、设备型号、操作结果和错误提示。

1. 在开发者工具使用具备预览权限的 AppID，点击 **预览**，由手机微信扫码打开。
2. 在设备页扫描附近设备。关闭蓝牙或拒绝权限时应显示明确提示，课程和商城仍可浏览。
3. 打开蓝牙并连接 BS-BT91。确认状态经过服务发现、订阅和输出频率校验，最终显示连接成功、频率接近 50 Hz，电量读取后显示百分比。
4. 将设备放在自然中心位置，点击 **校准中心** 并保持静止，直到出现「已完成中心校准」。
5. 关闭设备、主动断开或把小程序切到后台。确认训练资格撤销。回前台时重连设备，确认重新通过输出校验和中心校准。
6. 在条件允许时用不同固件或厂家工具预置非 50 Hz 输出，确认连接后会重新配置并复核。两台同名设备同时广播时，确认列表可区分且只连接选中的设备。

## 四方挥腕真机验收

1. 校准后切到「训练」，点击「进入训练」，再点击「开始训练」。核对 3 秒倒计时、左右前后四方向、目标环与保持进度。
2. 暂停几秒，再继续。确认暂停期间有效时长冻结，继续后需要重新满足完整的目标保持时间。
3. 训练中切到后台或关闭设备。回到页面时应仍暂停。在训练页重连同一台设备、重新校准，再点击「继续训练」。
4. 完成一局，核对有效时长、成功率、反应和到达时间。点击「查看训练回放」，检查动态播放、进度拖动及完整轨迹。
5. 重启微信后从「我的」打开同一条历史。检查本地摘要和回放仍存在，并确认删除会同步清除回放文件。
6. 分别记录 Android 与 iOS 的操作系统和微信版本、低帧率表现与长局运行情况。现场已反馈一部手机通过设备扫描、连接、频率、电量、中心校准以及四方挥腕基本训练要求。手机系统及另一平台的结果待补录。

## 8字轨迹跟随真机验收

1. 连接 BS-BT91 并完成中心校准，在「训练」选择「8字轨迹跟随」。确认倒计时结束后蓝色引导点每 20 秒完成一圈，绿色圆点随左右、前后挥腕移动。
2. 中途暂停、切后台和断开设备，观察有效时长是否冻结。回前台重连同一台设备并校准后继续，确认引导点从暂停位置继续移动。
3. 完成 60 秒训练，检查范围内比例、跟随偏差、范围内时间和有效样本。打开历史回放，核对播放、拖动进度条和完整轨迹视图中的蓝色参考路径与绿色实测轨迹。

## 森林溪谷漂流和欢乐卡丁车真机验收

1. 「森林溪谷漂流」确认倒计时后河道开始滚动，左右、前后挥腕分别移动小船，拾取金币和撞到障碍会更新 HUD。完成 90 秒后检查金币、碰撞、方向参与度和本机保存状态。
2. 「欢乐卡丁车」确认左右转向、前挥加速和后挥减速。检查弯道、终点、金币、护盾和加速道具。到达终点或触及最长训练时间后，核对完成方式、赛道进度、金币和碰撞统计。
3. 两款游戏均在训练中切换前后台或断开设备，核对画面和计时是否暂停。恢复后用同一台设备重新校准，再继续当前局。
4. 完成后从「我的」分别打开两款游戏的记录。检查回放播放、拖动定位与完整轨迹，确认金币、道具和碰撞显示与训练过程一致。

## 目录与本地数据

可在本机配置 `TARO_APP_API_BASE` 使用微信公众平台已登记的 HTTPS 请求域名。构建时可填域名根地址，也可填后端部署文档中的 `https://game.zhiwellcare.com/api/v1` 基址。设备、游戏、设备可用游戏使用 Go 的公开接口，目录请求失败时使用内置快照。启用在线目录后，训练大厅按后端上架状态和设备能力展示已接入的项目。训练摘要上报和个人云端历史需登录用户身份，当前训练历史仓储只使用微信本地文件和存储。「我的」页面提供本机数据用途说明。

训练记录摘要与回放文件分开存放。真机还需验证重启后读取、存储不足、删除后回放清理和较长训练回放的读取耗时。
